# nanolize 简洁版进度页：实施计划

状态：计划，未动代码。基于分支 `frontend-restyle`（末端 `02c3e552`）。

## 0. 目标和范围

打开 nanolize 的前端链接，先看到的是一个新的简洁页面：一片由真实功能图画成的星空，颜色随进度变化，下面一条进度条。页面上有一个按钮通向现在的详细页面。

- **产品里**：按钮通向同一台本机服务上的详细页面（现在的 run 页面，换到 `/detail`）。
- **公开预览里**：按钮通向 `https://ggeeyyi.github.io/nanolize-frontend-restyle/`。

不在这次范围内：选择页、报告页、轨迹页本身不改；详细页面只加一个回到简洁页的链接。

## 1. 现有前端能提供什么（调研结论）

| 需要的东西 | 现在有没有 | 在哪 |
|---|---|---|
| 运行的整体状态：六个阶段各自的状态、当前阶段、是否结束、是否在等人 | 有 | `/api/run` 的 `model`、`flow.focus`、`flow.milestones` |
| 提交之后的功能图：节点（id、名称、父节点、是否保留、说明、文件）、每个节点挂的检查、每一轮的检查结果 | 有 | `/api/graph`（`run_dashboard._function_graph`），上限 400 个节点 |
| 节点状态的算法（原版基线是否通过、某一轮是否通过） | 有，但只在详细页的脚本内部 | `run-graph.js` 的 `nodeAssignment`、`nodeRound` |
| 现在谁在处理哪个节点（在设计测试、在写、排队） | 有 | `run-flow.js` 的 `liveLeaves(view)` |
| 选择规则（core / all 预设、勾选一个节点会连带哪些、哪些不能去掉） | 有，独立模块 | `planner.js`（`scopePreset`、`planCapabilities`、`graph().keepClosure`）；整组勾选在 `progressive-graph.js` 的 `selectGroup` |
| 提交选择的请求（幂等键、被范围检查拦下时要求写理由） | 有，独立模块 | `execution.js`；请求是 `POST /api/jobs`，run 页面服务会转给评审服务 |
| **提交之前**的功能图（做白色点云和 2D 树用） | **没有接口** | 数据只嵌在选择页的 HTML 里；`/api/graph` 在作业出现前返回“不可用” |
| 节点下面更细的东西（对外的类和函数） | 计划里有，接口里没有 | 计划的 `interface` 字段；`/api/graph` 的节点不带它 |
| “这个节点 author 写完了” | **没有直接记录**，要推出来 | `progress.ledger.groups[].requests[]`（并行组）、`progress.ledger.writes`（单次 author 调用） |
| 总进度百分比 | **没有** | 只有零散的比例（里程碑 6 个里到了几个、比较跑了多少项检查） |
| 回放演示（不跑真实任务也能看页面） | 有，但写死了只服务详细页 | `scripts/run_page_demo.py` |

真实规模（mini-swe-agent 那次运行的计划）：46 个能力节点（1 个根、8 个一级、37 个二级，其中 41 个是叶子），节点之间 106 条依赖，68 个文件，402 个对外的类和函数。主页设计 9 的星空每个形状是 280 到 450 颗星，量级正好对得上。

## 2. 页面的六个画面

页面是一个状态机，画面由 `/api/run` 和 `/api/graph` 的内容决定，不靠用户操作推进。

| # | 画面 | 什么时候出现 | 画什么 | 用到的数据 |
|---|---|---|---|---|
| 1 | 分析中 | 阶段 01 还在做，功能图还没有 | 只有远处的微尘；中间一行字说在做第几步（共 9 步） | `stages.discover.steps` |
| 2 | 分析完成 | 功能图有了，还没提交 | 白色的 3D 点云：全部节点，之间是依赖关系的细线；缓慢转动 | 新接口 `/api/plan` |
| 3 | 选择 | 运行在等人提交范围（`flow.focus` 为 `attention` 且 `what` 为 `submit`，并且不是无人值守） | 点云摊平成 2D 功能树：每个节点带勾选框，上方 Core / All 两个预设，右下 Submit | `/api/plan` + `planner.js` |
| 4 | 提交之后 | 作业出现 | 回到 3D，只留选中的节点，没选的失去连线、退成微尘；形状按留下的部分重新排开；全部是暗淡的白色 | `/api/graph` |
| 5 | 进行中 | 阶段 03 到 05 | 每个节点按自己的进度换颜色（见第 4 节）；正在被处理的节点轻轻闪动 | `/api/graph` + `progress` + `liveLeaves` |
| 6 | 结束 | 作业到了终态 | 全部通过：整棵树亮绿，沿着连线亮一遍（设计 9 结尾的那道光）。有缺口或失败：照实显示，不全绿 | `model.terminal`、最后一轮结果 |

特殊情况：

- **无人值守**（`review.unattended`）：范围由 host agent 代交，页面不问任何人，从画面 2 直接到画面 4。
- **运行中途等人**（比如 controller 提了问题）：简洁页只显示一条提示和通往详细页的按钮，回答在详细页做。
- **pair 模式**：草稿作业先写代码时，节点只闪动表示“草稿在写”，颜色等代码导入主作业后才变。

## 3. 一个点是什么

- **主星 = 能力节点**（功能图里的节点）。可以悬浮、在选择时可以勾选，颜色表示进度。分组节点比叶子大一点，颜色取它下面所有叶子里最靠后的那个状态。
- **小星 = 这个节点对外的类和函数**（计划里的 `interface`）。围在主星周围，用短线连着，颜色跟着主星走，亮度低一档，不能单独悬浮。它们让画面成为“点云”，同时每一颗都对应真实的东西。
- **微尘**：很暗的背景星，纯装饰，数量少，不参与任何交互。提交后没被选中的节点也退到这一层。
- 节点很多的仓库：小星总数封顶（约 1,200 颗，按节点均匀抽取），主星不封顶（接口本身上限 400）。

### 3D 布局

设计 9 的形状是程序凭空生成的；这里要从真实的树长出来，并且每次打开都一样。

1. 根在中心；一级节点的方向取球面上均匀分布的点，子树大的占的角度大一些。
2. 更深的节点沿父节点向外的方向排在一个锥面里，越往外枝越短。
3. 小星在主星周围的小球壳上均匀排开。
4. 主星之间做几轮互斥，避免重叠；整体缩放到舞台留有边距。
5. 随机数的种子取自计划的摘要（`manifest_sha256`），所以刷新、轮询都不会跳。
6. 提交后只对留下的节点重新排一次，位置用一秒多的时间滑过去。这一步就是“为了美观调整形状”。

### 绘制

- 和设计 9 一样用普通的 canvas 2D，自己做透视投影，不引入任何库（页面的安全策略只允许加载自己的脚本，包里也不想多带东西）。
- 光点用预先画好的光晕贴图，叠加方式是“变亮”；先画远的再画近的，近处的更大更亮。
- 视角：从略高于水平的位置看（约 17 度），绕竖轴慢慢转；鼠标按住可以拖着转，悬浮时停转。
- 颜色用设计 9 的原值：星白 `230,236,255`，品牌绿 `118,185,0`，结尾的亮绿是绿色向白色过渡的几档（`187,220,128`、`214,234,178`、`241,248,230`）。
- 页面不在前台时停止绘制；系统设置了“减少动态效果”时不转动、不闪动，只画静止的一帧。

## 4. 节点的状态和颜色

| 状态 | 颜色 | 判定 |
|---|---|---|
| 已选中，还没开始 | 暗淡的白 | `in_scope` 为真，其余条件都不满足 |
| 测试准备好了 | 稍亮的白，它的连线也亮一档 | 这个节点挂的检查在原版上都通过（`nodeAssignment` 得 `passed`），并且没有“缺少有效测试”的标记（`leaf_test` 为空） |
| author 写完了 | 暗淡的绿 | 这个节点出现在一个已完成的 author 请求的范围里（并行组的 `requests[].capabilities`，或单次调用的 `ledger.writes`）；不分范围的写法则在第一个候选版本保存时全部算写完 |
| 测试通过 | 明亮的绿（设计 9 结尾的绿） | 最新一轮有结果的全量比较里，这个节点的检查全部通过（`nodeRound` 得 `passed`） |
| 全部通过 | 整棵树亮绿，加一次沿线传播的光 | 作业成功结束，且所有保留的叶子都是“测试通过” |

需求里没说、但一定会遇到的情况（我的建议，见第 13 节第 3 问）：

| 情况 | 建议的画法 |
|---|---|
| 正在被处理（在设计测试、在写、在比较） | 颜色不变，亮度缓慢起伏；悬浮卡片里写明谁在做什么 |
| 写完了但测试没通过 | 红色的点（主题里“失败”的颜色） |
| 写完了但没法验证（缺有效测试、被豁免、只部分通过） | 保持暗绿，外面一圈黄色细环 |
| 修复之后又退步了 | 按最新一轮的结果显示，可以从亮绿退回暗绿或红 |
| 分组节点 | 取它下面叶子里最靠后的状态 |

这两个状态函数（`nodeAssignment`、`nodeRound`）现在在详细页脚本内部，要改成两个页面共用同一份，保证两边永远说的一样。

### 悬浮卡片

3D 和 2D 两种画面都有。内容：节点名称、一句说明、当前状态的文字、测试数（已通过 / 总数）、涉及的文件数和代码量、依赖哪些节点、现在有没有人在处理它。触屏上点一下固定，再点别处关闭。

## 5. 选择画面（2D 功能树）

- **变形**：相机转到正面，透视收成平面，主星滑到树的位置（用现有的 `tree-layout.js` 排），小星淡出。提交后反过来。
- **节点**：一行一个，勾选框加名称；分组可以折叠。节点用真正的网页元素叠在画布上，所以键盘能操作、读屏能读；连线画在画布上。
- **预设**：Core features、All features，和选择页同名同义。
- **规则完全复用 `planner.js`**：勾一个节点会连带勾上它的父节点和依赖；去掉一个节点会连带去掉它的子节点和依赖它的节点；基础节点和被连带保护的节点显示锁，不能去掉。
- **提交复用 `execution.js`**：同一个请求、同一个幂等键。服务端因范围检查拦下时，同样弹出“请写理由”。
- **提示不能丢**：选择页上有范围检查的提示和说明。简洁页在 Submit 旁边显示“有 N 条说明”，点开到详细页看全文；选择页规定不能提交的情况，这里同样不能提交。
- **不搬过来的**：关系图视图、搜索、聊天、导出、函数级展开。这些留在详细页，简洁页给入口。

## 6. 进度条

页面底部一条。左边是阶段（“阶段 3 / 6 · 冻结契约”），右边是百分比，条上有六个阶段的分隔刻度，条下面一行小字是三个真实的计数（测试就绪、已写、已通过，各是几个节点里的几个）。

现在没有总进度，需要定义。建议按阶段加权，阶段内按节点数算：

| 阶段 | 占比 | 阶段内怎么算 |
|---|---|---|
| 01 发现 | 12 | 9 个步骤里完成了几个 |
| 02 选择范围 | 6 | 提交即满 |
| 03 冻结契约 | 27 | 测试就绪的叶子数 / 保留的叶子数；契约封存即满 |
| 04 重写 | 25 | 写完的叶子数 / 保留的叶子数；第一个候选保存即满 |
| 05 验证与修复 | 25 | 通过的叶子数 / 保留的叶子数，取各轮里最好的一次 |
| 06 交付 | 5 | 交付即满 |

- 百分比只进不退（验证取历史最好的一轮），下面的三个计数始终是当前的真实值。
- 结束时：成功是 100%，绿色；有缺口交付是 100%，黄色，并写明“有缺口”；失败或取消则条停在原处，变红。

### 新接口 `/api/plan`

返回画点云和选择需要的最少内容：每个节点的 id、名称、父节点、说明、是否基础节点、依赖、文件数、代码量、对外的类和函数的名字；加上选择规则需要的几项（`manifest_sha256`、`retain_percent`、`mode`、`scope_policy`、当前的 `locked` / `excluded`）和提交需要的 `operation_contract_digest`。

- 提交前读评审的计划，提交后读作业冻结的计划，所以小星和说明在整个过程中都有。
- 和 `/api/graph` 一样不含命令和输出，要带页面的 cookie 才能读，只在本机回环地址上提供。

## 9. 测试

- **纯函数**：布局对同一份计划每次结果相同、节点不重叠；节点状态在各种记录组合下的结果；百分比的每一段和只进不退。
- **和详细页一致**：同一份 `/api/graph`，两个页面算出的每个节点状态相同。
- **选择**：对同一份计划，简洁页勾选后产生的 `locked` / `excluded` 与选择页完全一样；提交的请求体一致。
- **页面状态机**：喂不同的 `/api/run`，检查落在六个画面里的哪一个；无人值守时不出现选择画面。
- **服务端**：新路由、cookie、安全策略、资产清单、打包。
- **截图**：六个画面在桌面和手机宽度各一张，中文一套。
- **真实记录回放**：用 mini-swe-agent、tqdm、detectron2 三次真实运行的记录逐帧回放，核对每个时刻的颜色和百分比。
- 最后跑全量测试，和未改动的 main 逐条比对。

## 11. 风险

| 风险 | 对策 |
|---|---|
| 节点少的仓库点云太稀 | 小星用对外的类和函数补足；阶段 2 先用三个真实仓库验证 |
| “写完了”没有按节点的记录；不分范围的写法只能在候选保存时一起变绿 | 照实做，并在文档里写明；并行模式下是逐个范围变绿 |
| pair 模式里写和测试准备同时进行，顺序不是固定的 | 颜色（白到绿）跟“写没写”走，亮度跟“测试到哪一步”走，两者互不依赖 |
| 3D 里悬浮不好点中 | 悬浮时停转；只有主星可以悬浮；取离鼠标最近的主星 |
| 简洁页的选择漏掉选择页的规则或提示 | 规则和提交都复用现有模块，不重写；提示给入口；测试里逐项比对 |
| 两个页面对同一个节点说法不一 | 状态函数只有一份 |
| 回放器现在写死详细页 | 阶段 5 改成可换页面；演示数据要补上提交前的计划 |

## 12. 不做的事

- 不引入 WebGL 或第三方图形库。
- 不把选择页的全部功能搬到简洁页。
- 不改作业本身的任何行为；新接口只读。

## 13. 需要你定的三件事

1. **小星画什么**
   1. （建议）主星是能力节点，小星是节点对外的类和函数，另加少量装饰微尘。
   2. 只画能力节点。画面会很稀（mini-swe-agent 只有 46 个点）。
   3. 画到代码索引里的全部符号（上千个点）。需要再加接口，悬浮和性能都更难。
