Nanolize 主页的设计版本

同一个主页，首屏动画的几种做法。每个版本是完整的页面，点开即可对比。

  • 0当前主页同步到最新提交后的主页，没有改动，作为对照。打开
  • 1更长、更立体的星空在网页 0 的基础上：动画区加高；乱图阶段视角在星空内部，星和线从眼前一直铺到很远，简化时视角后退看全子图；点击改成视角靠近被点的那颗星，再自己退回。打开
  • 2每轮不同的形状在网页 0 的基础上：每一轮简化后留下的子图从六种形状里轮换出现（螺旋星系、鹦鹉螺、双螺旋、蜂窝晶格、神经元、带环行星），不会连续两轮相同；螺旋本身缩小并打散了一些。网址后加 ?shape=nautilus 等可以指定形状。打开
  • 3更淡的连线和更讲究的排版在网页 2 的基础上：连线改成极细的淡线，星是清晰的小亮点，第一眼是星空、第二眼才是线；被去掉的星留成较暗的星空，简化前后是同一个中心和轮廓，取景不动；首屏统一到一条中轴和一个版心，读数和三项数字重排。打开
  • 4更自然的检查和收尾动画在网页 3 的基础上：跑检查时，光沿着子图自己的连线从核心向外走，遇到分叉就分开，前端是柔光、后面渐隐；完成时不再有外扩的圆圈和十字闪光，整个子图从核心起柔和地亮一次，再像余烬一样暗下去。打开
  • 5树状的形状、换着标的仓库、新字体和标志在网页 4 的基础上：用项目的字体方案和 J-2 标志；每一轮讲的是九个仓库中的一个，中心和外围标的是它自己的名字和模块，读数是它自己的数字；留下的子图是从一个根向外生长的树，共五种（神经元、螺旋、橡树、海扇、支气管树）；绿色线调暗并从根向外渐弱；星空铺满首屏并向外延伸。网址后加 ?shape=oak、?repo=tqdm 可以指定形状和仓库。打开
  • 6代码旁的文件结构图、更立体的子图在网页 5 的基础上：开头显示代码时，左侧是这一轮那个仓库的真实文件结构图，代码化成星空时每一行有虚线引到星云里；留下的子图更有立体感（近处的枝更宽更亮、远处的更细更暗，近的在交叉处压过远的）。打开
  • 7以 nano 仓库收尾、真实代码、细节打磨在网页 6 的基础上：子图停留之后不再倒放，而是变成 nano 仓库——左边绿色的文件树、右边绿色的代码；开头换成各仓库自己的真实代码；读数的用词、子图上的名字、检查和收尾两道光、小窗口和手机上的显示、防火墙一节都按评审意见打磨。一轮约 31 秒，?t=26 到 ?t=30 是新的结尾。打开
  • 8更快的节奏、虚线引线、重画的 nano 代码图在网页 7 的基础上：一轮从 31.5 秒缩到 27.5 秒，代码变星空和子图变代码这两段映射各缩到约 2.5 秒，引线连上之后很快松开；去掉文件树上的实线箭头，回到每一行末尾的细虚线；结尾的 nano 代码图重画：淡绿的文字、更亮的绿色关键字、更暗的注释和字符串、不填色的细线图标。?t=22 到 ?t=27 是结尾。打开
  • 9虚线只在映射时出现、nano 代码也缓慢下滑在网页 8 的基础上：文件树静止时旁边不再有虚线；代码变星空时虚线从各行末尾长出来，一直伸到星上，连上后松开；结尾子图变成代码文件之后，绿色虚线依次收回各行、很快消失；nano 代码和开头的原始代码一样缓慢向下滚。一轮仍是 27.5 秒。打开
  • 10绿色的树停留更短在网页 9 的基础上只改了时间：绿色的 core 树长成、检查、亮过之后停留的时间从 7 秒缩到 4.5 秒，后面的结尾整段提前 2.5 秒，其余各段不变。一轮从 27.5 秒缩到 25 秒。打开
  • 11以 GitHub 仓库墙开场和收尾把 shaoteng 分支的改动合进网页 10：每一轮先是一面滚动的 GitHub 仓库墙，光标随机点中一个仓库，它飞到文件树上，接着进入这个仓库的动画；一轮结束又回到仓库墙。星空那一段按两倍速播放，跑马灯里的库名带 GitHub 标志并链接到各自的仓库。一轮连同仓库墙约 20 秒。?t=-1.1 是点击的那一刻。打开
  • 12nano 仓库收拢回 GitHub 仓库墙在网页 11 的基础上：一轮结尾，绿色的文件树和代码不再直接淡出，而是被一圈细线框收拢到它自己的文件夹上，再沿开头的路线飞回仓库墙里它被点中的位置，变回这个仓库的条目；墙在它周围重新出现（还是同一面墙），接着滚动两格，光标点下一个仓库。?t=23.8 到 ?t=25 是收拢，?t=-3.1&from=tqdm&repo=click 起是回到墙之后。打开
  • 13更宽、更立体的星空在网页 12 的基础上：中间的星空不再按正文那一栏来排，而是铺向窗口两侧。1440 宽的窗口上，绿色的树占窗口宽度的 63–86%（原来 37–52%），乱图伸到两边之外；高度没有增加。视点更低更近，近处的枝约是远处的 2.8 倍大，前景有失焦的柔光斑；乱图阶段视点在星群中间，树亮起前退到位。开头结尾的代码、仓库墙、收拢和手机上的画面不变。打开
  • 14nanolize 之后白色的星逐渐消失在网页 13 的基础上：星空被 nanolize 时，没有被保留的白色的星不再留在绿树周围。绿色长到哪里，那一带没被保留的星和它们的连线就开始均匀变暗（屏幕上约 1.3 秒），由根向外依次熄灭，最后一颗在 delivered 之前消失，之后不再出现。留下的只有不属于代码图的背景：细尘、远星和淡雾。?t=6 到 ?t=10.5 是消失的过程，?t=18 是只剩绿树的样子。打开
  • 15开头的白色代码分层上色在网页 14 的基础上：开头那一屏原仓库的白色代码，照结尾 nano 代码的办法分四层上色。关键字最亮，正文是中等的灰白，字符串暗一些，注释和文档字符串最暗，def 和 class 开头的行加粗。仍然只用白色，绿色只留给 nano 的代码。其余都没有动。打开
  • 16各仓库按自己的验收标准：nerfstudio 和 llm-awq 的结果和结果页在网页 15 的基础上：八个库的结果表后面加了一节 “Each repository, held to its own standard.”，一个面板、每个仓库一个标签，主页放主要结果，点 Full verification 进入各自的结果页。nerfstudio（16/results/nerfstudio/）：训练时没用过的视角下真值、原版渲染、nano 渲染的对比，源码 token 减少 54.5%，59 / 59 个行为检查组通过，三次训练对比里 PSNR 最多相差 0.18 dB。llm-awq（16/results/llm-awq/）：可改写代码的 token 减少 48.8%，CUDA 扩展原样保留，30 / 30 组行为检查、12 / 12 项性能指标通过；另在 H100 上验证了三个模型的 AWQ 搜索结果、INT4 权重和困惑度在原版和 nano 之间逐位相同。tqdm、detectron2、accelerate 三个标签已摆上，还没有内容。打开
  • 17用法改成虚拟终端、方法改成角色和 tools、去掉结果主表在网页 16 的基础上：“Any agent. Any repository.” 一节移到陈述段后面，是一个虚拟终端里的一行命令：agent（带标志）+ nanolize + 仓库名，agent 和仓库名各自上下循环滚动，命令行末尾的按键打开 nanolize 仓库的 README；方法一节的防火墙图换成论文总览图的简化版：左边四个角色，右边 40 个 tool 分八行不停滚动，被调用的 tool 和干活的角色一起亮；八个库的结果主表去掉，结果就是各仓库（Demos）一节。打开

版本 6 的设计评审报告：八位评审提出的改进建议，分“更贴合主题”和“更简洁高级”两部分。

在任一版本的网址后面加 ?t=秒数 可以把动画停在那一刻，例如 ?t=6 是简化前的星空，?t=18 是简化后留下的子图。
